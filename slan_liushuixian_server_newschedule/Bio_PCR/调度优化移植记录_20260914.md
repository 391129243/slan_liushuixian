## 阶段5：异常复位优化

### 5.1 PcrDetailFragment优化

**文件**: `app/src/main/java/com/paul/pipeline/fragment/PcrDetailFragment.java`

**改动**：sendBackTray()方法
```java
private boolean sendBackTray(){
    if(model.index.get()!=null) {
        int pcrindex = model.index.get();
        
        // 1. 自动复位设备
        boolean resetOk = PCRManager.getInstance().reset(pcrindex);
        if (resetOk && model.usererror.get() != null) {
            model.usererror.set(0);
        }
        
        // 2. 标记托盘异常（防止调度继续推进）
        APLManager.getInstance().NotifyPcrTrayError(pcrindex);
        
        // 3. 触发放回调度
        APLManager.getInstance().checkPcrFinishError(pcrindex);
        
        show("PCR " + pcrindex + " 等待调度放回！");
        return true;
    }
    return false;
}
```

**优化说明**：
- **自动复位**：异常设备需先reset清错、状态回FREE，调度的WORK_BACK才会取盘
- **标记异常**：先把托盘标为str_ERROR + 记errorDispatchindex，使checkTrayEnd跳过该托盘
- **防止推进**：改由checkTrayError取回并保持异常状态

## 核心优势

### 1. 解耦架构
- **问题**：原调度逻辑与databinding（ObservableField）强耦合
- **方案**：抽象SchedulingParams接口，调度引擎不依赖Android
- **收益**：可在纯JVM环境运行单测，提升开发效率

### 2. 状态机驱动
- **问题**：回调递归自链可能栈溢出，难以调试
- **方案**：状态机驱动的tick()方法，明确状态转移
- **收益**：代码更清晰，逻辑更易理解和维护

### 3. 异常处理优化
- **问题**：用户放回异常设备时，调度可能继续推进错误托盘
- **方案**：放回时自动复位 + NotifyXxxTrayError标记异常
- **收益**：防止调度继续处理异常托盘，改由错误处理流程接管

### 4. 保留样本信息
- **问题**：一键还盘清空所有数据，样本信息丢失
- **方案**：clearDataKeepSamples()保留样本列表
- **收益**：用户体验优化，还盘后样本信息不丢失
