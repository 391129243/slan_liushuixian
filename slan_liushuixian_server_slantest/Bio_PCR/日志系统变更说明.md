# 日志系统变更说明

## 变更日期
2026-09-06

## 变更概述

参考 6in1 项目的 v4.1 日志系统，对当前项目进行了以下改造：

1. ✅ **目录结构调整**：将日志从分散目录统一到日期目录结构
2. ✅ **取消 ARM 日志存储**：因为 logcat 已包含相同内容，避免重复
3. ✅ **保留 PCR/RNA 日志**：继续支持但迁移到新的目录结构
4. ✅ **添加 14 天自动清理**：基于日期目录的过期清理机制
5. ✅ **优化 logcat 文件切换**：改进文件大小（20MB）和日期切换逻辑

---

## 目录结构变更

### 变更前
```
/sdcard/Log/
├── LOGCAT/                    # logcat 日志（独立目录）
│   └── 2026-09-06-14-30-00.log
├── ARM/                       # ARM 日志（独立目录）❌
│   └── 2026-09-06-14-30-00.log
├── PCR/                       # PCR 日志（独立目录）
│   └── 2026-09-06-14-30-00.log
└── RNA/                       # RNA 日志（独立目录）
    └── 2026-09-06-14-30-00.log
```

### 变更后
```
/sdcard/Log/
└── 20260906/                  # 日期作为最外层目录
    ├── logcat/                # logcat 归入子目录
    │   └── 20260906-143000.log
    ├── PCR/                   # PCR 日志归入日期下
    │   └── 20260906-143000.log
    └── RNA/                   # RNA 日志归入日期下
        └── 20260906-143000.log
    # ARM/ 不再存在 ✅
```

### 收益

- ✅ **按日期整体拷贝**：拷贝一个日期目录（如 `/Log/20260906/`），即可带走当天全部日志
- ✅ **统一管理**：logcat 和模块日志在同一日期目录下，方便问题排查
- ✅ **避免重复**：取消 ARM 日志后，磁盘占用减少
- ✅ **自动清理**：14 天后整个日期目录自动删除，包含其下所有日志

## 清理机制

### 触发时机
1. **应用启动时**：`LogcatHelper.init()` 中调用 `deleteExpiredLogDirs()`
2. **日期变化时**：
   - logcat 切换文件时（`LogDumper.rotateLogFile()`）
   - PCR/RNA 切换文件时（`LogAPL.checkFileSize()`）
3. **手动触发**：调用 `LogcatHelper.getInstance().cleanOldLogs()`

### 清理规则
- 扫描 `/Log/` 下的所有目录
- 检查目录名是否为 `yyyyMMdd` 格式（8位数字）
- 删除超过 **14 天**的整个日期目录（递归删除）
- 非日期格式的目录（如旧的 `LOGCAT`、`ARM`、`PCR`、`RNA`）不会被清理

### 清理行为
```
/sdcard/Log/
├── 20260820/          ← 17天前，会被删除
├── 20260901/          ← 5天前，保留
├── 20260906/          ← 今天，保留
├── LOGCAT/            ← 旧目录，不会被自动删除（需手动清理）
├── ARM/               ← 旧目录，不会被自动删除
├── PCR/               ← 旧目录，不会被自动删除
└── RNA/               ← 旧目录，不会被自动删除
```

## 兼容性说明

### 旧日志目录
- 升级后，旧的 `/Log/LOGCAT/`、`/Log/ARM/`、`/Log/PCR/`、`/Log/RNA/` 目录**不会自动迁移**
- 旧日志保持原位，可以继续访问
- 新日志写入新结构：`/Log/yyyyMMdd/moduleName/`
- 旧目录不会被自动清理（因为不是 `yyyyMMdd` 格式），需手动清理或保留

### API 兼容性
- `LogcatHelper.getInstance(context)` - 保持不变
- `LogcatHelper.getInstance()` - **新增**，无参版本
- `LogcatHelper.start()` - 保持不变
- `LogcatHelper.stop()` - 保持不变
- `LogcatHelper.appendlog(type, text)` - 保持不变，但 `LOG_ARM` 不再支持
- `LogcatHelper.cleanOldLogs()` - **新增**，手动清理方法

### 行为变更
- **ARM 日志不再写入**：调用 `appendlog(LOG_ARM, text)` 不会产生任何文件（该常量已删除，编译会报错）
- **日志文件名格式变化**：从 `yyyy-MM-dd-HH-mm-ss.log` 改为 `yyyyMMdd-HHmmss.log`
- **文件切换逻辑变化**：logcat 从 100MB 改为 20MB
