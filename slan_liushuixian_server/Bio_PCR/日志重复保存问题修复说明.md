# 日志重复保存问题修复说明

## 问题描述

**现象：**
- `/sdcard/Log/20260907/PCR/` 目录下有日志文件
- `/sdcard/Log/20260907/PCR/SLAN_PCR1111/` 目录下也有相同内容的日志文件
- 日志被重复保存了两次

**示例：**
```
/sdcard/Log/20260907/
├── PCR/
│   └── 20260907-150000.log          ← 重复保存（问题）
└── PCR/
    └── SLAN_PCR1111/
        └── 20260907-150000.log      ← WSSLogHelper 保存（正确）
```

---

## 根本原因

### 重复保存的流程

**PCRLog(bin) / RNALog(bin) 消息处理：**

```
1. WSSModuleManager 接收二进制消息
   ↓
2. 调用 savePCRLogToFile() / saveRNALogToFile()
   → WSSLogHelper.saveLog()
   → 保存到：/Log/20260907/PCR/SLAN_PCR1111/xxx.log  ✅
   ↓
3. 发送 EventBus.post(LogMessageEvent)
   消息类型：EnumMessageEvent.WSS_LOGMessage
   ↓
4. APLService 订阅 LogMessageEvent  ❌
   → LogcatHelper.appendlog()
   → 保存到：/Log/20260907/PCR/xxx.log
   ↓
5. PipeMainActivity 订阅 LogMessageEvent  ❌
   → LogcatHelper.appendlog()
   → 保存到：/Log/20260907/PCR/xxx.log
   ↓
结果：同样的内容保存了 3 次！
```

### 为什么会重复？

1. **WSSLogHelper（新增）**：保存到按设备分目录 `/Log/yyyyMMdd/ModuleName/DeviceID/`
2. **LogcatHelper（原有）**：保存到模块目录 `/Log/yyyyMMdd/ModuleName/`
3. **两个订阅者都在处理二进制日志**，导致 LogcatHelper 重复保存

---

## 修复方案

### 方案：只保留 WSSLogHelper 保存二进制日志

**核心思路：**
- 二进制日志（PCRLog(bin)、RNALog(bin)）由 **WSSLogHelper** 保存
- 文本日志（PCRLog、RNALog）由 **LogcatHelper** 保存
- 在 EventBus 订阅者中跳过二进制日志，避免重复

**日志分类：**

| 日志类型 | 消息类型 | 保存方式 | 目录 |
|---------|---------|---------|------|
| **文本日志** | `EnumMessageEvent.WSS_Message` | LogcatHelper | `/Log/yyyyMMdd/PCR/` |
| **二进制日志** | `EnumMessageEvent.WSS_LOGMessage` | WSSLogHelper | `/Log/yyyyMMdd/PCR/DeviceID/` |

## 修复内容

### 1. 修改 APLService.java

**位置：** `app/src/main/java/com/paul/pipeline/service/APLService.java`

**修改1：添加导入**
```java
import com.winters.boweilibrary.autopipeline.enumtype.EnumMessageEvent;
```

**修改2：跳过二进制日志**

**修改前：**
```java
@Subscribe(threadMode = ThreadMode.MAIN)
public void onEvent(LogMessageEvent messageEvent) {
    if(messageEvent!=null){
        switch(messageEvent.getLogtype()){
            case ConstantData.LOG_PCR:
                LogcatHelper.getInstance(getApplicationContext())
                        .appendlog(messageEvent.getLogtype(), toLogString(messageEvent.getLogtext()));
                break;
            case ConstantData.LOG_RNA:
                LogcatHelper.getInstance(getApplicationContext())
                        .appendlog(messageEvent.getLogtype(), toLogString(messageEvent.getLogtext()));
                break;
        }
    }
}
```

**修改后：**
```java
@Subscribe(threadMode = ThreadMode.MAIN)
public void onEvent(LogMessageEvent messageEvent) {
    if(messageEvent!=null){
        // 只处理文本日志消息（WSS_Message），跳过二进制日志消息（WSS_LOGMessage）
        // 二进制日志已经由 WSSLogHelper 保存到 /Log/yyyyMMdd/ModuleName/DeviceID/ 目录
        if (messageEvent.getMsgType() == EnumMessageEvent.WSS_LOGMessage) {
            // 二进制日志（PCRLog(bin)/RNALog(bin)）已由 WSSLogHelper 保存，跳过
            return;
        }

        switch(messageEvent.getLogtype()){
            case ConstantData.LOG_PCR:
                LogcatHelper.getInstance(getApplicationContext())
                        .appendlog(messageEvent.getLogtype(), toLogString(messageEvent.getLogtext()));
                break;
            case ConstantData.LOG_RNA:
                LogcatHelper.getInstance(getApplicationContext())
                        .appendlog(messageEvent.getLogtype(), toLogString(messageEvent.getLogtext()));
                break;
        }
    }
}
```

## 注意事项

1. **文本日志和二进制日志是不同的**
   - 文本日志：来自文本消息（JSON 格式）
   - 二进制日志：来自二进制消息（byte[] 格式）
   - 内容可能不同

2. **目录结构的意义**
   - `/Log/yyyyMMdd/ModuleName/` - 模块级别的文本日志
   - `/Log/yyyyMMdd/ModuleName/DeviceID/` - 设备级别的二进制日志
   - 按设备分目录，便于追溯特定设备的问题

3. **EventBus 消息类型区分**
   - `EnumMessageEvent.WSS_Message` - 文本消息
   - `EnumMessageEvent.WSS_LOGMessage` - 二进制日志消息
   - 订阅者应该根据消息类型选择性处理
