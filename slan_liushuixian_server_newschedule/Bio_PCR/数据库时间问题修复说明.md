# 数据库时间存储问题修复说明

## 问题描述

**现象：**
- 界面显示的开始时间：`2026-09-07 15:16:24`（正确）
- 数据库存储的开始时间：`2026-09-07 23:10:40`（错误，早了约8小时）
- SharedPreferences 中的 `START_TIME` 是正确的

**影响范围：**
- 实验结果保存到数据库时，开始时间不正确
- 导致查询、统计、报表等功能中的时间数据错误

---

## 根本原因

### 主要原因：使用了 SLAN SDK 生成的时间戳

**位置：** `app/src/main/java/com/paul/pipeline/fragment/PcrCurveFragment.java:1984-1994`

**问题代码：**
```java
if (slanExperiment.getStartTime() == null) {
    String nowtime = DateFormatUtil.getSysFullTime();
    model.startTime.set(nowtime);
} else {
    long temp = Long.parseLong(slanExperiment.getStartTime());
    SimpleDateFormat format = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
    String startTime = format.format(temp/10000);
    model.startTime.set(startTime);
}
```

**问题分析：**
1. 从 `slanExperiment.getStartTime()` 获取时间，这是 SLAN SDK（客户端 slansdk）生成的时间戳
2. 该时间戳可能有时区问题，与服务器时区不一致
3. SimpleDateFormat 没有指定 Locale，在不同设备上行为不一致
4. **正确的做法应该是使用 SharedPreferences 中存储的时间**（用户点击提交按钮时记录的时间）

### 次要原因：DateFormatUtil.getSysFullTime() 实现问题

**位置：** `app/src/main/java/com/gidi/bio_pcr/util/DateFormatUtil.java:25-29`

**问题：** SimpleDateFormat 没有指定 Locale，可能导致时区问题

---

## 修复方案

### 方案：使用 SharedPreferences 中的开始时间

**核心思路：**
- 不再使用 `slanExperiment.getStartTime()`（SLAN SDK 生成的时间）
- 使用 `SharedPreferences.START_TIME`（用户点击提交按钮时记录的本地时间）
- 这样确保时间与界面显示一致

**修复后代码：**
```java
// 使用 SharedPreferences 中存储的开始时间（用户点击提交按钮的时间）
// 不使用 slanExperiment.getStartTime()，因为它是 SLAN SDK 生成的，可能有时区问题
String startTimeFromPrefs = PreferenceUtil.getInstance(getActivity())
        .getStringValue(SharedConstant.PCR_RUNNING_TEMPLATE_STARTTIME, "");

if (startTimeFromPrefs != null && !startTimeFromPrefs.isEmpty()) {
    model.startTime.set(startTimeFromPrefs);
    Log.i("slanFinish", "使用 SharedPreferences 中的开始时间: " + startTimeFromPrefs);
} else {
    // 如果 SharedPreferences 中没有，使用当前时间作为备用方案
    String nowtime = DateFormatUtil.getSysFullTime();
    model.startTime.set(nowtime);
    Log.w("slanFinish", "SharedPreferences 中没有开始时间，使用当前时间: " + nowtime);
}
```

## 技术要点

### 为什么不使用 SLAN SDK 的时间？

1. **客户端生成**：SLAN SDK 是客户端库，生成的时间戳可能与服务器时区不一致
2. **时区问题**：SDK 内部的时区处理逻辑不透明，难以控制
3. **精度问题**：代码中需要除以 10000（`temp/10000`），说明精度单位不明确
4. **不可靠**：依赖外部 SDK 的时间，不如使用本地记录的时间可靠

### 为什么使用 SharedPreferences？

1. **本地记录**：在用户点击提交按钮时记录，时间准确
2. **与界面一致**：界面显示的时间也来自同一个来源
3. **易于控制**：完全由应用自己控制，不受外部影响
4. **可追溯**：可以随时查看和调试 SharedPreferences 中的值

### SimpleDateFormat 线程安全问题

**问题：**
```java
private static SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
```

`SimpleDateFormat` 不是线程安全的，多线程使用同一个实例会导致数据错乱。

**DateFormatUtil 的修复：**
```java
public static String getSysFullTime(){
    // 每次创建新实例，避免线程安全问题
    SimpleDateFormat localSdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss", Locale.CHINA);
    return localSdf.format(System.currentTimeMillis());
}
```

## 时区处理原则

### ✅ 正确做法

1. **创建 SimpleDateFormat 时指定 Locale**
   ```java
   SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss", Locale.CHINA);
   ```

2. **使用系统当前时区**
   - 不显式调用 `setTimeZone()`
   - 让 SimpleDateFormat 使用设备的当前时区
   - 这样可以确保时间与设备显示一致

3. **避免时区重复转换**
   - `System.currentTimeMillis()` 返回的是 UTC 时间戳
   - SimpleDateFormat 会自动根据时区转换显示
   - 不要手动再做一次时区转换

### ❌ 错误做法

1. **不指定 Locale**
   ```java
   SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"); // ❌
   ```

2. **错误设置时区**
   ```java
   sdf.setTimeZone(TimeZone.getTimeZone("GMT+08:00")); // ❌ 可能导致重复转换
   ```

3. **使用共享的 SimpleDateFormat 实例**
   ```java
   private static SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"); // ❌ 线程不安全
   ```

## 技术要点

### SimpleDateFormat 线程安全问题

**问题：**
```java
private static SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
```

`SimpleDateFormat` 不是线程安全的，多线程使用同一个实例会导致数据错乱。

**解决方案：**
1. **方案1：每次创建新实例（推荐）**
   ```java
   public static String getSysFullTime(){
       SimpleDateFormat localSdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss", Locale.CHINA);
       return localSdf.format(System.currentTimeMillis());
   }
   ```

2. **方案2：使用 ThreadLocal**
   ```java
   private static ThreadLocal<SimpleDateFormat> sdfThreadLocal = ThreadLocal.withInitial(
       () -> new SimpleDateFormat("yyyy-MM-dd HH:mm:ss", Locale.CHINA)
   );
   ```

3. **方案3：使用 Java 8+ 的 DateTimeFormatter（推荐）**
   ```java
   DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
   LocalDateTime.now().format(formatter);
   ```

### Locale 的重要性

不指定 Locale 会导致：
- 在不同语言环境的设备上行为不一致
- 月份名称、星期名称等可能显示为当地语言
- 数字格式可能不同

**最佳实践：**
```java
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss", Locale.CHINA);
```
