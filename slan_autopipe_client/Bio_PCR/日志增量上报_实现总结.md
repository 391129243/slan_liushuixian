## 一、功能概述

### 1.1 核心目标

实现日志文件的**增量上传**到主控服务器，采用：
- **二进制传输**（参考 server 端 `PCRLogMessage`）
- **混合触发策略**（参考 6in1）：定时30秒 OR 积累16KB
- **进度持久化**（避免重复上传和数据丢失）

### 2.2 二进制序列化格式

```
+------------------+
| JSON 头部        |  UTF-8编码的JSON（不含fileData）
+------------------+
| \r\n\r\n        |  分隔符
+------------------+
| 二进制数据       |  fileData 字节数组
+------------------+
```

**序列化代码**：
```java
private ByteBuffer serializeBinMessage(BinBaseMessage msg) {
    String jsonHeader = String.format(...); // 构造JSON头
    byte[] headerBytes = jsonHeader.getBytes("UTF-8");
    byte[] separator = "\r\n\r\n".getBytes("UTF-8");
    byte[] fileData = msg.getFileData();
    
    ByteBuffer buffer = ByteBuffer.allocate(headerBytes.length + separator.length + fileData.length);
    buffer.put(headerBytes);
    buffer.put(separator);
    buffer.put(fileData);
    buffer.flip();
    return buffer;
}
```

## 三、上传策略

### 3.1 混合触发机制

| 策略 | 条件 | 目的 |
|------|------|------|
| **定时触发** | 距离上次上传 ≥ 30秒 | 保证实时性，即使日志量少也能及时上传 |
| **缓冲触发** | 待上传数据 ≥ 16KB | 提高效率，减少频繁小包传输 |

**检查周期**：每10秒检查一次（比30秒间隔更灵敏）

**决策流程**：
```
每10秒 → checkAndUpload()
  ├─ 计算待上传字节数（所有文件的增量和）
  ├─ 判断：已过30秒？ → 是 → 立即上传
  └─ 判断：积累≥16KB？ → 是 → 立即上传
```

### 3.2 配置常量

```java
private static final long UPLOAD_INTERVAL_MS = 30 * 1000;      // 定时30秒
private static final long UPLOAD_BUFFER_THRESHOLD = 16 * 1024; // 缓冲16KB
```

**可调整性**：
- 高频场景（调试）：改为 `10秒 + 8KB`
- 低频场景（生产）：改为 `60秒 + 32KB`

## 四、进度持久化

### 4.1 为什么需要持久化？

| 场景 | 无持久化 | 有持久化 |
|------|---------|---------|
| App重启 | 重头上传，重复数据 | 从上次断点继续 |
| 上传失败 | 下次重传整个文件 | 只传失败的增量 |
| 网络波动 | 数据重复或丢失 | 保证exactly-once |

### 4.2 实现方式

**存储**：`SharedPreferences`
- Key: `log_pos_<文件绝对路径>`
- Value: `已上传的字节位置（long）`

**示例**：
```
log_pos_/storage/emulated/0/Log/2026-09-07/14-30-15.log = 4096
log_pos_/storage/emulated/0/Log/2026-09-07/15-20-30.log = 8192
```

**生命周期**：
```
App启动 → loadUploadProgress() → 从 SharedPreferences 加载到 mUploadProgressMap
上传成功 → saveUploadProgress() → 更新 SharedPreferences
```

### 4.3 精确字节读取

```java
FileInputStream fis = new FileInputStream(logFile);
long readPos = mUploadProgressMap.getOrDefault(filePath, 0L);
fis.skip(readPos); // 跳过已上传的部分

byte[] buffer = new byte[16 * 1024]; // 每次最多读16KB
int bytesRead = fis.read(buffer);

// 上传成功后更新进度
mUploadProgressMap.put(filePath, readPos + bytesRead);
saveUploadProgress(filePath, readPos + bytesRead);
```

**关键**：使用 `FileInputStream.skip()` 精确定位，避免：
- ❌ 每次从头读取（浪费I/O）
- ❌ 行分割读取（可能断行丢失数据）

## 七、性能优化

### 7.1 单次上传限制

```java
int chunkSize = (int) Math.min(fileLength - readPos, 16 * 1024);
```

**目的**：
- 避免单次上传过大（影响UI响应）
- 与缓冲触发阈值一致（16KB）

### 7.2 定时器优化

```java
mUploadTimer = new Timer("LogUploadTimer", true); // true = 守护线程
```

**优势**：
- 守护线程，不阻止 App 退出
- 异步执行，不占用主线程

### 7.3 内存管理

```java
private final Map<String, Long> mUploadProgressMap = new HashMap<>();
```

**注意事项**：
- 每个日志文件一个 entry
- 长期运行可能积累较多条目
- **建议**：定期清理超过14天的文件进度记录

private void cleanExpiredProgress() {
    Calendar calendar = Calendar.getInstance();
    calendar.add(Calendar.DAY_OF_MONTH, -SDCARD_LOG_FILE_SAVE_DAYS);
    String expireDateStr = dateDirSdf.format(calendar.getTime());
    
    Iterator<Map.Entry<String, Long>> it = mUploadProgressMap.entrySet().iterator();
    while (it.hasNext()) {
        Map.Entry<String, Long> entry = it.next();
        String filePath = entry.getKey();
        // 提取日期判断是否过期

        }
    }
}
