# 流水线日志存储与格式说明（server / client）

> 面向后续 Python 分析工具：通过 adb 拉取日志，或 U 盘拷贝日志后离线分析。
> 所有路径中的 `/sdcard` 即 `Environment.getExternalStorageDirectory()`，在设备上通常是 `/storage/emulated/0`。
> 编码统一为 UTF-8（Java 默认 charset，设备为 UTF-8），换行符为 `\n`（LF）。

---

## 1. 总览

| 设备 | 应用包名 | 角色 |
|---|---|---|
| 流水线主控（server） | `com.gidi.bio_pcr` | 调度、收集各模组上报的日志 |
| PCR client | `com.gzlab.autoassemblyline_client` | 宏石 PCR 仪器端，定时把本地 logcat 增量上报给 server |
| RNA client | 同 PCR client 代码体系（deviceId 为 `RNA1111`/`RNA2222`） | 核提端，上报方式与 PCR 相同 |

设备 ID 固定：

- PCR：`SLANPCR1111` ~ `SLANPCR6666`（对应位置 1~6）
- RNA：`RNA1111`、`RNA2222`

## 2. 目录结构

### 2.1 server（主控）

```
/sdcard/Log/                              ← 日志根目录（外置存储未挂载时回退到 filesDir/Log/）
└── yyyyMMdd/                             ← 按天分目录，例 20261116
    ├── logcat/                           ← server 自身进程的 logcat
    │   └── yyyyMMdd-HHmmss.log           ← 单文件 20MB 滚动
    ├── PCR/                              ← 文本消息 PCRLog 的整段 JSON（appendlog 写入）
    │   └── yyyyMMdd-HHmmss.log           ← 单文件 100MB 滚动
    ├── RNA/                              ← 同上，RNA 文本消息
    │   └── yyyyMMdd-HHmmss.log
    ├── PCR/<DeviceID>/                   ← 二进制 PCRLog 上报的日志正文（WSSLogHelper）
    │   └── yyyyMMdd-HHmmss.log           ← 单文件 20MB 滚动，例 PCR/SLANPCR1111/
    └── RNA/<DeviceID>/                   ← 二进制 RNALog 上报的日志正文
        └── yyyyMMdd-HHmmss.log

/sdcard/PCR/Log/                          ← server 崩溃日志（CrashHandler）
└── yyyy-MM-dd-HH-mm-ss_crash.txt

/sdcard/PCR/Template/                     ← PCR 模板文件（非日志）
/sdcard/PCR/database/                     ← 数据库文件（非日志）
/sdcard/Log/BinLog/                       ← 旧版二进制日志目录（代码中仅有清理逻辑，当前不再写入）
```

### 2.2 client（PCR / RNA 仪器端）

```
/sdcard/Log/                              ← client 自身 logcat（外置存储未挂载时回退 filesDir/Log/）
└── yyyy-MM-dd/                           ← 注意：client 日期目录带横杠，与 server 不同
    └── HH-mm-ss.log                      ← 单文件 20MB 滚动

/sdcard/PCR_CONTROL/Log/                  ← client 崩溃日志
└── yyyy-MM-dd-HH-mm-ss_crash.txt

/sdcard/PCR_CONTROL/Update/               ← 升级包目录（非日志）
/sdcard/PCR/Template/、/sdcard/PCR/database/   ← 同 server
```

**server 与 client 目录命名差异（解析时注意）**：

| | server | client |
|---|---|---|
| 日期目录 | `yyyyMMdd`（`20261116`） | `yyyy-MM-dd`（`2026-11-16`） |
| 文件名 | `yyyyMMdd-HHmmss.log` | `HH-mm-ss.log` |
| 崩溃目录 | `/sdcard/PCR/Log/` | `/sdcard/PCR_CONTROL/Log/` |

## 3. 各日志的行格式

### 3.1 logcat 转储（server `/Log/<日>/logcat/`、client `/Log/<日>/`）

每行格式：

```
<时间戳>   <logcat 原始行>\n
```

- 时间戳：`yyyy-MM-dd HH:mm:ss`（`DateFormatUtil.getSysFullTime()`，系统本地时区，不转换）
- 时间戳与 logcat 行之间是 **3 个空格**
- logcat 原始行未指定 `-v` 格式，取设备默认格式（threadtime），典型形态：

```
2026-11-16 00:05:12   11-16 00:05:12.345  1234  5678 I WSSModuleManager: HeartBeatReply PCR: key=SLANPCR1111 moduleKey=SLANPCR1111 isEnabled=true
```

- 只保留包含本进程 PID 的行（`line.contains(pid)`），所以日志里只有本应用进程的输出
- 级别过滤：server 抓 `*:e *:w *:i *:d`（Verbose 被丢弃）；client 抓 `*:e *:i`（Debug/Verbose 被丢弃）
- 代码里的过滤命令带 `| grep`，但 `Runtime.exec(String)` 不走 shell，管道实际不生效，真正生效的是上面的 PID 过滤

### 3.2 server 文本消息日志（`/Log/<日>/PCR/`、`/Log/<日>/RNA/`）

来源：client 发来的文本型 `PCRLog`/`RNALog` 消息（整段 JSON），由 `APLService` 收到 `WSS_Message` 事件后经 `LogcatHelper.appendlog()` 写入。

- 文件开头第一行是一个时间戳（`yyyy-MM-dd HH:mm:ss`，无换行语义，紧接内容）
- 之后每条消息写入 `消息文本 + " \n"`（注意：空格 + 换行）
- 消息文本是原始 JSON 字符串；若内容是 `byte[]` 则写成 Base64
- 写入是异步缓冲的（StringBuffer 攒一批再写），同一秒内的多条会连在一起
- **跨天不立即切目录**：只有文件超过 100MB 时才检查日期，所以这个目录里可能出现"文件名是昨天、内容跨到今天"的情况

### 3.3 server 二进制上报日志（`/Log/<日>/PCR/<DeviceID>/`、`/Log/<日>/RNA/<DeviceID>/`）

来源：client 通过二进制通道增量上报的 logcat 正文（见第 4 节），由 `WSSLogHelper.saveLog()` 写入。**这是分析 client 行为最有用的日志**，因为内容就是 client 的 logcat。

每条上报块写成一行：

```
<时间戳> [<DeviceID>] <日志正文>\n
```

例：

```
2026-11-16 00:05:30 [SLANPCR1111] 2026-11-16 00:05:12   11-16 00:05:12.100  2345  2345 I SLANModuleManager: ...\n2026-11-16 00:05:13   ...
```

解析注意：

- 一条记录内部的"日志正文"本身含有 `\n`（client 一次最多上报 16KB，包含多行 logcat），所以**不能按行切分**。应按记录头正则切分：`^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2} \[[A-Za-z0-9]+\] `
- 正文是 client logcat 文件的原始字节（UTF-8），格式同 3.1
- 去重：≥256 字节的内容块，10 分钟窗口内相同（hashCode+长度）会丢弃并在 server logcat 打 `检测到重复日志块，丢弃`。短行不去重
- 写入队列容量 1000，满了丢弃并打 `日志队列已满，丢弃日志`
- 磁盘可用空间 < 500MB 时静默丢弃（`StorageMonitor` 熔断），不留痕迹
- 文件按修改时间找"最新的 .log"续写，超过 20MB 新建

### 3.4 崩溃日志（server `/sdcard/PCR/Log/`、client `/sdcard/PCR_CONTROL/Log/`）

文件名：`yyyy-MM-dd-HH-mm-ss_crash.txt`，纯文本，不被自动清理（client 明确跳过；server 的 14 天清理只扫 `/Log/` 下的日期目录，不碰这里）。

server 内容：

```
2026-11-16 00:05:12          ← 崩溃时间
App version: x.x.x - 123     ← versionName - versionCode
OS version: 7.1.2 - 25       ← RELEASE - SDK_INT
Vendor: <厂商>
Model: <型号>

<异常 printStackTrace>
```

client 内容更全，额外有：`Thread: <名> (id=<id>)`、`Exception type:`、`Exception msg :`、`CPU ABI:`，并带 `Stack trace:` 小标题。

server 崩溃后还会尝试 FTP 上报该文件（`FtpUploadManager`）。

## 4. client → server 日志上报协议（PCRLog 二进制消息）

client 的 `LogcatHelper` 定时把本地 logcat 文件的增量通过 WSS 二进制消息发给 server：

- 触发：每 10 秒检查一次；距上次发送 ≥ 30 秒，或待上传 ≥ 16KB，二者满足其一即发送
- WSS 未连接时跳过（不读文件），连接恢复后从已保存的进度继续。进度存在 SharedPreferences `LogUploadProgress`（key `log_pos_<绝对路径>`，value 为已上传字节偏移）
- 每次最多读 16KB，按文件修改时间从旧到新逐个文件上传
- 发送失败不推进进度，下次重试同一段（所以 server 端做了去重）

二进制帧格式（大端）：

```
偏移  长度   内容
0     4     魔数 0x5AA5FCFF
4     4     JSON 头长度 N
8     N     JSON 头（UTF-8，PCRLogMessage 的 Gson 序列化，不含 FileData）
8+N   ...   文件数据（UTF-8 文本，即 logcat 增量）
```

JSON 头关键字段：

| 字段 | 示例 | 说明 |
|---|---|---|
| Type | `"PCRLog"` / `"RNALog"` | 消息类型 |
| SeqID | 12345 | 序列号 |
| DeviceID | `"SLANPCR1111"` | 设备 ID，决定 server 落盘子目录 |
| DeviceType | `"PCR"` | |
| Position | `1` | 位置 1~6 |
| FileName | `"2026-11-16/14-30-15.log"` | client 上的相对路径（相对 `/Log/`） |
| FileSize | `4096` | 本帧文件数据字节数 |
| CheckSum | `"<md5>"` | 文件数据的 MD5 |

server 收到后：取 `DeviceID`（为空则用连接项的 deviceID），把文件数据按 UTF-8 解码，交给 `WSSLogHelper.saveLog("PCR"|"RNA", deviceID, 内容)` 落盘（见 3.3）。

另有文本型 `PCRLog`/`RNALog`（JSON 文本帧，旧路径），server 会把整段 JSON 写入 `/Log/<日>/PCR|RNA/`（见 3.2），正常运行时走的是二进制路径。

## 5. 保留策略与磁盘保护（server）

| 机制 | 行为 |
|---|---|
| 常规清理 | `/Log/` 下日期目录（`yyyyMMdd`）超过 **14 天**整目录删除。触发点：server 启动、logcat 跨天滚动时。仅外置存储模式生效 |
| client 清理 | `/Log/` 下 `yyyy-MM-dd` 目录超过 **10 天**删除（代码注释写 14，常量实际是 10）。crash 的 .txt 文件不删 |
| 磁盘熔断 | 可用空间 < 500MB：拒绝写二进制日志 + 紧急清理（先删 3 天前、仍不足再删 1 天前的 `/Log/` 文件）；< 1GB 打警告 |
| 日志总量 | `/Log/` 总大小超过 2GB 触发常规清理 |
| 紧急清理依据 | 按文件 `lastModified` 时间，不是目录名日期 |

## 6. 关键 TAG 与事件字符串（分析时的锚点）

server 侧（logcat TAG → 关键日志）：

| TAG | 字符串 | 含义 |
|---|---|---|
| `WSSModuleManager` | `HeartBeatReply PCR: key= moduleKey= isEnabled=` | PCR 心跳回复，含启用状态 |
| | `QueryDeviceReply` | 设备查询回复 |
| | `RestartPCRAppReply: key= deviceID= reply=ok` | client 确认收到重启指令 |
| | `RNAAck OK` | RNA 应答 |
| | `【PCRLog(bin)】收到日志: key= file= deviceID= size=` | 收到 client 二进制日志上报 |
| | `保存 PCR 日志成功: deviceID= size= 耗时=` | 落盘成功 |
| | `检测到重复日志块，丢弃` | 去重丢弃（WSSLogHelper TAG） |
| `PCRRestart` | `已下发重启指令` / `调度占用中，推迟重启` / `重启指令发送失败` | 每日 00:00 PCR client 重启调度（忙则推迟到空闲） |
| `ArmTaskWorker` | `执行刷新后台任务` | 调度周期任务 |
| `PcrApplication` | `restart system` | server 崩溃后重启 |
| `StorageMonitor` | `磁盘空间严重不足` / `开始紧急清理` | 磁盘保护触发 |
| `SLANModuleManager`（经 WSS） | `deviceID= template=`（实验结束） | SLAN 实验完成 |

client 侧：

| TAG | 字符串 | 含义 |
|---|---|---|
| `WSSModuleManager` | `收到重启App消息` / `===1000ms 后重启App===` / `restartApp: 已调度重启` | 收到 server 重启指令并执行 |
| | `强制重启：先停止正在运行的实验` / `实验运行中，拒绝重启App` | 重启时实验状态处理 |
| | `连接状态不一致` | WSS 连接状态异常 |
| | `PCRLog消息发送成功` / `PCRLog发送失败: WSS未连接` | 日志上报结果 |
| `LogcatHelper` | `========== PCRLog 上报触发 ==========`（含触发原因、字节数） | 上报周期触发 |
| | `WSS未连接，跳过本轮日志上传` | 断连期间跳过 |
| `CrashHandler` | `崩溃日志已保存: <路径>` | 崩溃落盘 |

## 7. adb 拉取 / U 盘拷贝

### 7.1 adb 拉取

```bash
# 当天 server 全部日志（主控设备）
adb -s <server序列号> pull /sdcard/Log/<yyyyMMdd>/ ./server_<yyyyMMdd>/
# server 崩溃日志
adb -s <server序列号> pull /sdcard/PCR/Log/ ./server_crash/

# client（PCR 仪器，日期目录带横杠）
adb -s <client序列号> pull /sdcard/Log/<yyyy-MM-dd>/ ./client_<deviceID>/
adb -s <client序列号> pull /sdcard/PCR_CONTROL/Log/ ./client_crash/
```

实时跟踪：`adb logcat -v threadtime | grep -E "WSSModuleManager|PCRRestart|SLANModuleManager"`

### 7.2 U 盘拷贝

server 有 USB 文件浏览/导出界面（设置里的文件列表），拷贝 `/sdcard/Log/` 整个日期目录即可，一天的 server 日志 + 当天各 client 上报的日志都在里面。

### 7.3 建议的拉取目录布局（给分析工具）

```
logs/
├── server/
│   ├── 20261116/            ← 原样保留 /sdcard/Log/20261116/
│   └── crash/
└── client/
    ├── SLANPCR1111/2026-11-16/
    └── crash/
```

注意：client 的日志在 server 侧已有一份副本（`/Log/<日>/PCR/<DeviceID>/`），只有在需要 client 侧原始文件或 server 未收到上报（断连、去重、熔断丢弃）时才需要单独拉 client。

## 8. 给 Python 解析器的要点

1. **两条切分规则**：
   - logcat 文件（3.1、3.2）：按 `\n` 分行，行首 `^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})   (.*)$` 提取时间戳与正文
   - 二进制上报文件（3.3）：按记录头 `^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) \[([A-Za-z0-9]+)\] ` 切块（正文跨行），块内正文再按 3.1 规则拆
2. logcat 正文解析用 threadtime：`日期 时间 PID TID 级别 TAG: 消息`，级别为单个大写字母
3. 时间戳都是设备本地时间，无时区信息；server 与 client 若未对时，同一事件的时间会有偏差，关联时以消息内容（DeviceID、SeqID）为准
4. 文件可能正在被写入（当前最新文件），拉取时最后一条记录可能不完整，解析应容忍截断
5. 3.2 的文本日志文件首行是孤立时间戳，且消息间分隔符是 `" \n"`（空格+换行）
6. 崩溃文件是多行自由文本，按文件名时间 + `Exception type`/`printStackTrace` 关键字提取即可
