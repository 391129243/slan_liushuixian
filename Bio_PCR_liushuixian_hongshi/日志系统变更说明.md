# 日志系统变更说明

## 变更日期
2026-09-06

## 变更概述

参考工程 `slan_liushuixian_server/Bio_PCR` 的日志系统（其自身参考 6in1 v4.1），对本工程
`Bio_PCR_liushuixian_hongshi` 进行了以下改造：

1. ✅ **目录结构调整**：日志从分散目录（`/Log/LOGCAT`、`/Log/ARM`、`/Log/PCR`、`/Log/RNA`）统一到日期目录结构 `/Log/yyyyMMdd/模块/`
2. ✅ **取消 ARM 独立日志文件**：ARM 内容已在 logcat 中，改为直写 logcat，避免重复落盘
3. ✅ **保留 PCR/RNA 日志**：迁移到新的日期目录结构
4. ✅ **14 天自动清理**：基于日期目录的过期清理机制（原为 10 天、基于单文件）
5. ✅ **优化文件切换**：logcat 20MB、PCR/RNA 100MB，且支持跨天自动切换目录
6. ✅ **修复重复写入 Bug（本工程特有）**：`PipeMainActivity` 与 `APLService` 曾同时订阅
   `LogMessageEvent` 并各写一次，导致 bin 日志被写两遍。本次改造**只保留 `APLService`
   作为唯一写入方**（参考工程尚未修此 Bug，本工程更优）

### 变更前
```
/sdcard/Log/
├── LOGCAT/                    # logcat 日志（独立目录）
│   └── 2026-09-06-14-30-00.log
├── ARM/                       # ARM 日志（独立目录）❌ 与 logcat 重复
│   └── 2026-09-06-14-30-00.log
├── PCR/
│   └── 2026-09-06-14-30-00.log
└── RNA/
    └── 2026-09-06-14-30-00.log
```

### 变更后
```
/sdcard/Log/
└── 20260906/                  # 日期作为最外层目录
    ├── logcat/
    │   └── 20260906-143000.log
    ├── PCR/
    │   └── 20260906-143000.log
    └── RNA/
        └── 20260906-143000.log
```

### 收益

- ✅ **统一管理**：logcat 与模块日志同处一个日期目录
- ✅ **避免重复**：取消 ARM 独立文件 + 修复 bin 日志双写
- ✅ **自动清理**：14 天后整个日期目录递归删除

## 清理机制

### 触发时机
1. **应用启动时**：`LogcatHelper.init()` 调用 `deleteExpiredLogDirs()`
2. **日期变化时**：logcat 切文件（`rotateLogFile()`）、PCR/RNA 切文件（`checkFileSize()`）
3. **手动触发**：`LogcatHelper.getInstance().cleanOldLogs()`

### 清理规则
- 扫描 `/Log/` 下所有目录，目录名匹配 `yyyyMMdd`（8 位数字）
- 删除超过 **14 天** 的整个日期目录（递归）
- 非日期格式目录（旧的 `LOGCAT/`、`ARM/`、`PCR/`、`RNA/`）**不会被自动清理**

## 兼容性说明

- 旧目录 `/Log/LOGCAT`、`/Log/ARM`、`/Log/PCR`、`/Log/RNA` 不会自动迁移，保持原位可继续访问
- 新日志写入 `/Log/yyyyMMdd/模块/`
- 文件名格式：`yyyy-MM-dd-HH-mm-ss.log` → `yyyyMMdd-HHmmss.log`
- API：`getInstance(context)` / `start()` / `stop()` / `appendlog(type,text)` 保持兼容；
  新增无参 `getInstance()` 与 `cleanOldLogs()`；`LOG_ARM` 已移除（编译期不可用）

## 与参考工程的差异（重要）

参考工程 `slan_liushuixian_server/Bio_PCR` 的 `日志系统变更说明.md` 中，`APLService`
**和** `PipeMainActivity` **都**保留了 `appendlog` 调用 —— 这实际上会导致 `WSS_LOGMessage`
类型的 bin 日志被写入两次（两个订阅者同时存活）。

本工程在移植时**修复了这一点**：只保留 `APLService` 作为唯一写入方，`PipeMainActivity`
的 `LogMessageEvent` 订阅整体删除。因此本工程的日志系统在"去重"方面优于参考工程。

> 后续若反向同步回参考工程，建议一并移除其 `PipeMainActivity.onEvent(LogMessageEvent)`。
